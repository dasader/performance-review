### 재현

```
GET https://api.openalex.org/works
  filter=title_and_abstract.search:{검색식},publication_year:2025,
         authorships.institutions.country_code:{KR|US|CN}
  per-page=1&select=id     → meta.count
```
검색식은 `backend/alembic/versions/0010_national_strategic_tech_2026.py`의 `SUBFIELDS`.
콤마·파이프를 공백으로 치환해야 한다(`openalex._sanitize_query`와 동일).
콜당 $0.001이므로 55×3 = 165콜 = $0.165. **OpenAlex는 연속 호출 시 429를 낸다 —
호출 간 0.4초 이상 간격과 백오프를 둘 것.**

## 3. 5,000건 상한과 정렬

`sort=cited_by_count:desc`가 **cursor 페이징과 병용된다**(실측: 1페이지 끝 79회 →
2페이지 시작 79회로 단조감소 유지). 비용은 동일.

연도별 정규화는 자동 성립한다 — `runner.enqueue()`가 이미 연도마다 별도 `Analysis`를
만들고 단일 연도만 검색하므로, 정렬 대상이 항상 한 연도 안이다.

당해연도도 정렬이 유효하다: 2026년 CN 재생에너지 18,003건의 인용 상위가 41·34·33회이고
상위 200건에 0인용이 없다.

**현행 절단은 무작위가 아니다.** OpenAlex 기본 정렬(`relevance_score`)이 인용수를
반영한다 — 기본 정렬 200건의 인용 중앙값 56, 0인용 0건, 인용 정렬 상위 200과 46% 중복.
다만 relevance는 불투명한 점수라 국가 비교의 기준선으로는 쓸 수 없다.

## 4. abstract 결측 — 원인은 Elsevier 게재 비중

`has_abstract` 필터 + `group_by`로 **전수** 집계(2025년).

| 세부기술 | KR | US | CN | JP | DE |
|---|---:|---:|---:|---:|---:|
| 재생에너지 | 38.5% | 21.4% | 35.5% | 23.2% | 15.3% |
| 차세대 메모리반도체 | 19.4% | 8.2% | 21.1% | 8.1% | 13.4% |
| 효율적 AI 학습 및 추론 | 14.0% | 11.8% | 26.1% | 21.5% | 13.6% |
| 세포·유전자 치료 | 21.9% | 19.7% | 25.0% | 18.9% | 16.2% |

**국가 특성이 아니다.** CN 재생에너지 25,466건 분해:

| 분해축 | 결과 | 판정 |
|---|---|---|
| Elsevier 게재분 | 7,383건(29.0%) 중 **81.9% 결측** | **원인** |
| Elsevier 제외 | 18,083건 중 16.6% 결측 | 5배 차이 |
| Wiley·MDPI·ACS·IEEE·IOP | 각 0.0~0.1% | 무관 |
| `conference-paper` | 5,738건 중 **7.2%** | 학회논문 가설 기각(`article` 38.8%보다 낮음) |
| `preprint` | 1,716건 중 95.8% | 비중 6.7%라 기여 작음 |
| 언어 `Chinese` | **99건(0.4%)** 중 1.0% | 중문 가설 기각 |

전체 결측 9,053건 중 Elsevier가 6,046건 = **66.8%**. Elsevier가 Crossref에 초록을
예치하지 않기 때문이다. 국가별 결측률 순위 = Elsevier 게재 비중 순위
(KR 32.0% > CN 29.0% > JP 22.1% > DE 18.5% > US 17.9%).

> **주의**: 인용 상위 표본으로 결측률을 재면 방향이 뒤집힌다(표본 기준 CN 41% > KR 34%,
> 전수 기준 KR 38.5% > CN 35.5%). 인용이 높은 논문일수록 특정 출판사에 몰려 있다.
> **결측률은 반드시 `has_abstract` 전수 집계로 잴 것.**

### 재현

```
filter=...,has_abstract:false                        → 결측 건수
filter=...,has_abstract:false&group_by=type          → 유형별 결측
filter=...&group_by=primary_location.source.host_organization   → 출판사별
Elsevier host_organization = https://openalex.org/P4310320990
```

## 5. 초록 회수 — Elsevier 무료 API가 88% 회수한다

무료 경로 실측(OpenAlex 결측 논문 DOI로 조회):

| 소스 | 공학 | 바이오 |
|---|---:|---:|
| Crossref | 0% | — |
| Semantic Scholar | 2% | — |
| OpenAIRE | 8% | — |
| CORE / Scilit | 키 필요(429) / 403 차단 | — |
| OA 사본 존재 | 8% | — |
| **Europe PMC** | 3~27% | **73~93%** |

Europe PMC 세부: 세포·유전자 치료 93%, 차세대 백신 87%, 합성생물학 73%,
재생에너지 27%, 효율적 AI 13%, 차세대 메모리반도체 3%.

### Elsevier 공식 API

키 없이 호출하면 HTTP 200에 메타데이터만 오고 초록이 빈다. 헤더가 이유를 밝힌다:
```
x-els-status: WARNING - Unauthorized request results in minimized metadata response.
```

**무료 등록 키로 재시험한 결과 두 API의 동작이 갈린다:**

| API | 결과 |
|---|---|
| Scopus Abstract Retrieval (`view=FULL`) | HTTP **401** — 기관 구독 필요 |
| 엔타이틀먼트 조회 엔드포인트 | HTTP **403** — 이 키에 기관 자격 없음 |
| **ScienceDirect Article Retrieval** | **35/40건 초록 회수 (88%)** |

- 표본: Crossref에 초록이 없는 Elsevier(10.1016) 2025 저널논문 40건. 두 번 실행해 동일 재현.
- 회수 초록 평균 1,940자(765~5,958). **`openaccess=0`(구독 전용)에서도 나온다.**
- 실패 5건 = 404 2건(ScienceDirect 미수록) + 200이나 초록 없음 3건.
- 확인 사살: `10.1016/j.patcog.2025.111512`(OpenAlex 결측, OA=0) → 1,388자 회수.

**전문은 구독이 필요하지만 초록은 무료 키로 열려 있다.**

동시성 실측(지연 건당 0.31s, 문서상 한도 10 req/s):
동시성 1 → 3.0 req/s, **3 → 9.5 req/s(429 없음)**, 5 → 14.6 req/s(429 발생).

한도: ScienceDirect Article Retrieval 주당 50,000건(텍스트마이닝 키는 무제한).
필요 물량은 KR 연 약 3,000건, 5개국 약 4만 건이라 **한 주치 안**에 들어온다.

> **함정**: Crossref로 대상 DOI를 뽑을 때 `until-pub-date`를 빼면 2026년 온라인
> 선공개분이 잡혀 전량 404가 난다. 회수율을 잴 때는 발행 연도를 양쪽으로 막을 것.

## 6. 보고서가 논문 수를 소화하지 못한다

DB의 완성된 분석 110건 전수 집계.

| 규모 | 평균 논문 | 평균 자수 | 평균 인용 편수 | 인용률 |
|---|---:|---:|---:|---:|
| <30 | 16 | 6,758 | 15.0 | 102% |
| 30–99 | 59 | 8,093 | 26.3 | 48% |
| 100–199 | 150 | 10,702 | 38.4 | 25.8% |
| 200–349 | 254 | 11,077 | 43.1 | 17.6% |
| 350–499 | 412 | 11,612 | 39.8 | 9.7% |
| 500–799 (3단) | 617 | 10,256 | 35.0 | 5.6% |
| 800+ (3단) | 1,112 | 10,362 | 38.0 | 3.8% |

**논문이 16편이든 1,112편이든 약 40편만 인용하고 약 11,000자에서 멈춘다.**
재생에너지 2025는 1,323건을 분석해 8,305자·25편으로, 708건짜리(13,951자·58편)보다 짧다.

**출력 상한 때문이 아니다** — 상위 8개 보고서가 전부 문장 완결로 끝난다(잘림 없음).
최대 18,892자 ≈ 9,400토큰으로 `gemini_max_output_tokens`(16,000)에 여유가 있다.
따라서 상한 상향이나 프롬프트 강화로는 해결되지 않는다.

**입력은 문제가 아니다.** 5,000건도 약 375,000토큰으로 컨텍스트(1M)에 여유.
현행 3단 reduce는 500건씩 끊어 컨텍스트의 4%만 쓴다.

### 정량 수치는 98.8%가 소실된다

`paper_extractions.metrics_json`에 수치 **33,796개**가 이미 있다(추출 22,059건 중
11,721건 = 53.1%가 수치 보유). **`stats.compute`는 이를 하나도 집계하지 않는다.**

| 규모 | 추출된 수치 | 보고서 표 행 | 반영률 |
|---|---:|---:|---:|
| 100–199 | 245 | 11 | 4.9% |
| 500+ | 1,206 | 11 | **1.2%** |
| 5,000건이면 | 약 8,000 | 11 | **0.14%** |

### 재현

```sql
-- 인용 편수: 괄호 안 15~250자를 인용으로 근사
SELECT (SELECT count(DISTINCT m[1])
        FROM regexp_matches(a.report_md,'\(([^()]{15,250})\)','g') m)
FROM analyses a WHERE a.report_md IS NOT NULL;

-- 보고서 표 행 수
SELECT count(*) FROM regexp_matches(a.report_md,'^\|[^|]+\|[^|]+\|[^|]+\|','gm');

-- 추출된 수치 총량
SELECT sum(jsonb_array_length(metrics_json::jsonb)) FROM paper_extractions;
```
DB 접속: `docker compose exec -T db psql -U perfrev -d perfrev`

## 7. 지표명 정규화 — 사후 청소보다 추출 통제가 141배 싸다

지표명이 자유 문자열이라 그대로는 집계가 안 된다. 재생에너지 2025(수치 2,323개)를
코드 정규화만 돌리면 **1,809그룹, 70%가 1건짜리**이고 PCE가 7조각으로 갈린다
(`전력 변환 효율` 82 / `power conversion efficiency` 45 / `pce` 31 / `광전변환효율` 20 / …).
단위도 328종, 전류밀도만 14변형이며 `μA cm–2`와 `A cm-2`가 섞여 있다.

원인은 지표명에 물리량이 아닌 것이 섞이는 것: `Single-junction PSC PCE`,
`AlGaAs 밴드갭 에너지`, `댐프 히트(85 °C/85% RH) 테스트 후 효율 유지율`.

### (가) 사후 LLM 정규화 — 2,116쌍 전체 실측

품질은 좋다. 최대 그룹 82개 → **425개(원본 294종 통합)**, 5.2배.
단위 변형 통합 정상, **위험한 오변환 0건**("확신 없으면 바꾸지 말라" 지시가 작동).

**그러나 분석당 $0.198(272초)이고 캐시가 안 듣는다** — 재생에너지 2026과 겹치는 쌍이
1,283개 중 81개(**6.3%**), 코드 정규화 키로도 12.2%. 550분석 기준 **회당 약 $109**.

### (나) 추출 단계 통제 — 실제 논문 25편 A/B

| | 현행 프롬프트 | 통제 프롬프트 |
|---|---:|---:|
| 고유 지표명 | 56종 | **34종** |
| 2회 이상 등장 지표에 속한 수치 | 9개 (15%) | **31개 (57%)** |
| 고유 단위 | 18종 | **12종** |
| 비ASCII 단위 | 6종 | **0종** |
| map 비용 | $0.0114 | $0.0130 (+14%) |

map +14% = KR 전체 연 **+$0.77**. 사후 정규화 회당 $109과 **141배 차이**.
→ **(나)를 택한다.**

### 곁가지 — `achievement_type` enum 오염

9종 지정인데 **17종**이 저장돼 있다(`회로설계`/`회로 설계`, `데이터셋`/`데이터셋 구축`,
`소자` 등 17건). 이 값이 3단 reduce의 그룹 분할 키라 그룹이 불필요하게 늘어난다.
분포도 치우쳐 있다(알고리즘 24.5%, 시스템구현 22.0%).

#### 부수 확인

`효율 유지율` 최대 101.9%, `개방전압` 최대 3.3V처럼 물리적으로 의심스러운 값이 섞인다.

### 전체 재실행 결과 (2026-08-03) — 3단계 효과의 전수 확인

110건 전부 재실행. **실패 0건**, OpenAlex $0.4830(잔여 5,170).

| | 이전 | 이번 | 증감 |
|---|---:|---:|---:|
| 검색 | 31,769 | 31,740 | **-29** |

**검색 총계는 그대로인데 분석만 22% 늘었다.** 증가분이 전부 Elsevier 초록 회수에서
왔다는 뜻이다 — 새 논문이 잡혀서가 아니다. 3단계 효과를 이보다 깨끗하게 분리해
보여주는 수치는 없다. 회수 실적은 **4,561건 대상 → 4,468건(98.0%)**으로,
CCUS 단건 검증(100%)이 전수에서도 유지됐다.

예상은 +13%였는데 실제는 +22.2%다. 예상치는 CCUS 한 건에서 외삽한 것이라
Elsevier 게재 비중이 높은 분야를 과소평가했다.

#### 효과는 에너지·전지·바이오에 몰린다

| 세부기술 | 이전 | 이번 | 증가 |
|---|---:|---:|---:|

#### 3단 reduce가 2건 → 12건으로 늘었다

500건 경계를 넘은 분석이 6배가 됐다. 그런데 그 12건의 종합 보고서 길이가 이렇다.

| 세부기술 | 분석 | 종합 | 세부 합계 |
|---|---:|---:|---:|
| 재생에너지 2025 | 1,850 | 4,681 | 138,842 |
| 청정수소 2025 | 1,551 | 5,565 | 155,728 |
| 세포·유전자 치료 2025 | 862 | 4,688 | 133,054 |
| 바이오 데이터·AI 2026 | 501 | 5,043 | 111,083 |
| *(참고)* 차세대 메모리반도체 2025 | 245 | **10,549** | 없음 |

**종합 보고서 길이가 분석 건수와 무관하게 약 5,000자에서 포화한다.** 501건이든
1,850건이든 같다. 그리고 단일 reduce로 끝난 245건짜리가 그 두 배(10,549자)다.

§1의 "정량 표가 논문 수와 무관하게 11~12행에서 포화"와 같은 현상이 보고서 전체
길이에서 반복된 것이다. **논문 수와 종합 보고서 길이 사이에는 관계가 없고, 오히려
음의 방향으로 보인다** — 3단 reduce에 들어가는 순간 최종 통합이 그룹 요약만 보기
때문이다. 실질 내용은 세부 보고서 11만~15만 자에 있다.

이것이 5단계 비교 보고서에 직접 영향을 준다:

- **종합 보고서 길이를 정보량·연구 깊이의 대리 지표로 쓰면 안 된다.** 이전에는
  CN만 3단이라 국가 간 문제로 보였는데, 이제 KR도 12건이 같은 압축을 겪는다.
  비교 대상 세부기술의 한쪽만 3단이면 길이 차가 구조적으로 발생한다.
- 계획서([5단계 계획](superpowers/plans/2026-08-03-country-comparison-reports.md))의
  판단 — 세부 보고서를 LLM 입력에 넣지 않고 `COMPARE_INSTRUCTION`이 길이 오독을
  금지 — 은 그대로 유효하고, 근거가 12건으로 더 두터워졌다.

### 계획에 없던 작업 — 운영 중 발견한 결함 2건

로드맵에 없었으나 재추출을 돌리다 드러나 먼저 고쳤다. **둘 다 4단계(다국가 확장)에서
훨씬 크게 터졌을 문제다** — CN 한 국가만 126청크라 batch가 상시 떠 있게 된다.

| # | 문제 | 수정 |
|---|---|---|
| PR #6 | `Retry-After`가 43,579초(약 12시간)로 와서 `get_with_retry`가 그만큼 `sleep` → `runner.loop()`가 활성 분석을 순차 `await`하므로 **110건 전부와 batch 폴링·`resume_paused`까지 정지** | 잔여 요청 수·잔여 예산 중 하나라도 0이면, 또는 `Retry-After`가 `HTTP_MAX_RETRY_AFTER_SECONDS`(300초)를 넘으면 `permanent`로 올려 `paused` → 자정 재개 |
| PR #7 | `enqueue`의 force 분기가 `batch_job_id`를 무조건 비워, 추출 중 "지금 실행"을 누르면 **돌고 있는(=과금되는) Gemini 잡의 핸들을 잃고 같은 청크를 재제출** | `batch_job_id`가 있고 상태가 `ACTIVE_STATES`면 force를 무시. `failed` 행은 죽은 잡이므로 예외 |

기존 크레딧 소진 판정이 `X-RateLimit-Remaining`만 봐서 놓쳤다는 점이 PR #6의 핵심이다 —
실측에서 요청 수는 4가 남았는데 `X-RateLimit-Remaining-USD`가 0.0004였다.
근거는 코드 주석과 `CLAUDE.md`("429는 절대 오래 기다리지 않는다", "프리즈 없는 증분 갱신")에 남겼다.

## 10. 5단계 완료 후 검토할 항목 — 정량 지표

2026-08-02에 확인했으나 **일부러 구현하지 않은** 것들. 로드맵 5단계(국가 비교 보고서)가
끝난 뒤 함께 검토한다. 셋이 서로 얽혀 있어 따로 손대면 두 번 일하게 된다.

### 10-1. 지표별 논문 목록 드릴다운 — 가능하다

화면의 지표 표는 "전력변환효율(PCE) 447편"까지만 보여주고 **어느 논문인지는 알 수 없다.**

**데이터는 이미 전부 있다.** `paper_extractions.paper_key`가 논문을 가리키고,
`metrics_json[].target`(v3부터, 99.9% 채워짐)이 측정 대상을 담는다. `aggregate_metrics`가
집계하면서 그 연결을 버릴 뿐이다.

구현 방향 — **저장하지 말고 조회 시점에 계산한다**:

```
GET /api/analyses/{id}/metrics?name=전력변환효율&unit=%
→ [{value, target, paper_title, doi}, ...]
```

`stats._metric_key`를 재사용해 같은 정규화로 묶으면 표의 숫자와 정확히 일치한다.
`stats_json`에 논문 키를 넣는 방식은 쓰지 않는다 — PCE 하나만 447개 키라 blob이
MB 단위로 부풀고 재계산 때마다 커진다.

규모는 엔드포인트 1개 + 화면 드릴다운(논문 수를 누르면 펼침).

### 10-2. 원자료 이상값 — 자동 필터링은 불가능하고 위험하다

`효율 유지율` 101.9%, PCE 최소 0.24% 같은 값이 섞인다. **대부분 오류가 아니다.**

재생에너지 2025의 PCE 이상값을 `target`과 함께 조회한 실측:

| 값 | target | 정체 |
|---:|---|---|
| 97.3% | Z-소스 통합 결합 인덕터 **쿡 컨버터** | **전력변환 회로 효율** — 태양전지 PCE가 아님 |
| 96% | 48V/260V/200W **컨버터 시스템** | 〃 |
| 85% | 2.45 GHz **마그네트론** | 〃 |
| 1.67% | Mn/Co 도핑 **CdS 양자점 태양전지** | 진짜 태양전지 (초기 단계 재료라 정상) |
| 1.3% | 600-800nm 파장 범위 태양전지 | 〃 |

**"전력변환효율"이라는 같은 이름 아래 태양전지 PCE와 전력회로 변환효율이 섞였다.**
값이 틀린 게 아니라 서로 다른 물리량이 한 그룹에 묶인 것이다.

기계적 필터링을 하면 안 되는 이유:
- 배터리 용량 유지율이 활성화 과정에서 100%를 넘는 것은 **실제 현상**이다.
- PCE 1.3%도 신규 재료에서는 정상값이다.
- 값만 보고는 "오류"와 "다른 대상"을 구분할 수 없다.

→ **지우지 말고 검증 가능하게 만든다.** 10-1의 드릴다운이 그 수단이다. "97.3%가 왜
여기 있지?"를 눌러보면 "컨버터구나"가 5초에 판명된다. `target` 기반 자동 분리도
생각할 수 있으나 세부기술마다 사전을 관리해야 해서, §7에서 기각한 것과 같은 함정이다.

### 10-3. 범위 표기 값 — 하한만 반영된다

값에 `"4-6"` 같은 범위 표기가 섞인다. `stats._metric_value`가 첫 숫자만 취해 `4`로
집계한다. 틀린 값은 아니지만 하한만 반영되는 셈이다. 빈도와 영향은 아직 측정하지 않았다.
