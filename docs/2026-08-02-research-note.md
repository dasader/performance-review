# 연구노트 — 2026-08-01/02

다국가 확장 설계에서 시작해 로드맵 1~4단계 구현·검증까지 이어진 이틀의 기록.
**결론만이 아니라 무엇을 시도했고 무엇이 틀렸는지**를 남긴다 — 나중에 같은 길을
다시 걷지 않기 위해서다.

PR 19건(#4~#22), 커밋 65개.

비용은 **OpenAlex만 실측**된다(`openalex_usage`가 매 응답의 `meta.cost_usd`를 누적) —
**$0.4980**, 잔여 크레딧 5,019. **Gemini는 누적 테이블이 없어 추정**이다(재추출 map 약 $6 +
보고서 재생성 약 $1.5 + CN 실행 약 $0.2 ≈ $7.7). 다국가로 넓히면 Gemini가 지배적 비용이
되므로 **`openalex_usage`와 같은 실측 누적을 Gemini에도 붙이는 것이 5단계 전에 할 만하다**.

## 1. 출발점 — "다국가로 넓히면 무엇이 깨지는가"

처음 질문은 "미국·중국·일본으로 확장하고 싶다"였다. 답을 추측으로 쓰지 않고
**OpenAlex를 직접 두드려 실측**하는 쪽을 택했다. 55개 중점기술 × KR/US/CN 전수(165콜, $0.165).

이 선택이 이후 모든 결정의 근거가 됐다. 특히 세 가지가 추측과 달랐다.

**배수가 분야마다 전혀 다르다.** 총량으로는 CN이 KR의 8.5배지만, 차세대 OLED는
KR 288 / US 198로 **한국이 더 많다.** 무기발광 디스플레이·친환경 선박도 그렇다.
"확장하면 어디나 압도당한다"는 전제가 데이터로 틀렸고, 이것이 비교 보고서의
가치를 뒷받침한다.

**5,000건 상한이 곧바로 문제가 된다.** CN 11개·US 3개 세부기술이 상한을 넘는데,
현행 코드는 그것을 `AnalysisTooLarge`로 **거부**한다. 확장하면 그 14개가 그냥 실패한다.

**논문 수만으로는 국가를 비교할 수 없다.** 교신저자 소속국을 보니 **일본 논문의 47%가
자국이 주도하지 않은 국제공동연구**였고 중국은 7.5%였다. 참여 기준만 쓰면 두 나라의
"몇 건"을 같은 의미로 읽게 된다.

## 2. 가설 검증 — 세 번 틀렸다

### 2-1. abstract 결측의 원인 (중문? 학회논문? → 둘 다 아님)

"중국 논문의 초록 결측이 41%"라는 관찰에서 출발했다. 가설은 중문 논문, 학회논문,
특정 유형이었다. `has_abstract` 필터 + `group_by`로 전수 분해했더니:

| 가설 | 결과 | 판정 |
|---|---|---|
| 중문 논문 | 중문은 **99건(0.4%)**뿐, 결측률 1.0% | **기각** |
| 학회논문 | `conference-paper` 결측률 **7.2%** (`article` 38.8%보다 낮음) | **기각** |
| 출판사 Elsevier | 7,383건 중 **81.9% 결측**, Elsevier 제외는 16.6% | **원인** |

**결측의 66.8%가 단일 출판사였다.** Elsevier가 Crossref에 초록을 예치하지 않기 때문이고,
국가별 결측률 순위는 Elsevier 게재 비중 순위와 거의 일치한다.

> **표본이 방향을 뒤집었다.** 처음엔 인용 상위 200건 표본으로 "CN 41% > KR 34%"라고
> 적었는데, 전수로 재니 **KR 38.5% > CN 35.5%**로 반대였다. 인용이 높은 논문일수록
> 특정 출판사에 몰려 있다. 결측률은 반드시 전수로 재야 한다.

### 2-2. Elsevier 초록 회수 (구독 필요? → 무료 키로 88%)

무료 경로를 전부 두드렸다: Crossref 0%, Semantic Scholar 2%, OpenAIRE 8%,
Europe PMC는 바이오만 73~93%. 공학은 답이 없었다.

Elsevier 공식 API를 키 없이 호출하니 HTTP 200에 초록만 비었고, 헤더가 이유를 밝혔다:

```
x-els-status: WARNING - Unauthorized request results in minimized metadata response.
```

여기서 **"구독 자격이 유일한 관문"이라고 결론 냈다가 틀렸다.** 사용자가 무료 키를
주어 다시 시험하니:

| API | 결과 |
|---|---|
| Scopus Abstract Retrieval | HTTP 401 — 기관 구독 필요 |
| **ScienceDirect Article Retrieval** | **35/40건 회수 (88%)** |

**전문은 구독이 필요하지만 초록은 무료 키로 열려 있었다.** 우리에게 필요한 건 초록뿐이라
구독·insttoken·IP 대역 문제가 전부 비껴갔다. 실제 배포 후 CCUS 2026에서 **129/129(100%)**,
CN 논문에서도 84/84(100%)로 나왔다.

### 2-3. 지표명 정규화 (사후 청소? → 추출 통제가 141배 싸다)

정량 지표를 집계하려니 지표명이 자유 문자열이라 같은 PCE가 7조각으로 갈렸다
(`전력 변환 효율` 82 / `power conversion efficiency` 45 / `pce` 31 / …).

두 방법을 **둘 다 실제로 돌려** 비교했다.

| | 사후 LLM 정규화 | 추출 단계 통제 |
|---|---|---|
| 품질 | 최대 그룹 82 → 425개 | 집계 가능 수치 15% → 57% |
| 비용 | 분석당 $0.198, **캐시 히트 6.3%** → 회당 약 $109 | map +14% = 연 **+$0.77** |

캐시가 안 듣는 이유를 파고들자 원인이 드러났다 — **지표명에 물질·조건이 섞여 있어**
논문이 바뀌면 이름도 바뀐다(`Single-junction PSC PCE`, `AlGaAs 밴드갭 에너지`).
사후에 청소할 게 아니라 애초에 안 묻히게 하는 것이 맞았다.

`MAP_INSTRUCTION`에 규칙을 넣고 `target` 필드를 분리했다. 재추출 후 **PCE가 447건
단일 그룹**으로 묶였다 — 폐기했던 사후 정규화(425건)보다 많고 비용은 1/141이다.

## 3. 운영 중 드러난 결함 4건

계획에 없었으나 재추출을 돌리다 발견해 먼저 고쳤다. **넷 다 다국가 확장에서 훨씬 크게
터졌을 문제**다 — CN 한 국가만 126청크라 batch가 상시 떠 있게 된다.

### 3-1. 긴 `Retry-After`가 잡 루프 전체를 멈춤 (PR #6)

재추출 시작 직후 OpenAlex가 `Retry-After: 43579`(약 12시간)를 반환했고
`get_with_retry`가 그만큼 잤다. `runner.loop()`는 활성 분석을 순차 `await`하므로
**110건 전부와 batch 폴링·`resume_paused`까지 정지**했다.

기존 크레딧 소진 판정이 있었는데도 안 걸린 이유: **요청 수만 봤다.**
실측 헤더는 `remaining: 4`(0 아님)인데 `remaining-usd: 0.0004`였다.

→ 두 헤더를 함께 보고, `Retry-After`가 상한(300초)을 넘으면 기다리지 않고
`permanent`로 올려 기존 `paused`/자정 재개 경로로 흐르게 했다.

### 3-2. force 재실행이 진행 중 batch를 고아로 만듦 (PR #7)

`enqueue`의 force 분기가 `batch_job_id`를 무조건 비운다. 추출 중에 "지금 실행"을
누르면 **돌고 있는(=과금되는) Gemini 잡의 핸들을 잃고 같은 청크를 재제출**한다.

→ `batch_job_id`가 있고 `ACTIVE_STATES`인 행은 force를 무시한다.
`failed` 행은 죽은 잡이므로 예외로 뒀다.

### 3-3. 연결 실패에 재시도가 없음 (PR #9)

`httpx.ConnectError` 한 번에 분석 2건이 `search_attempts=0`인 채로 죽었다.
`get_with_retry`가 **재시도 루프 안에 있으면서도** 네트워크 오류에서 즉시 탈출했다 —
429는 5회 재시도하는데 연결 실패는 한 번도 안 했다.

→ `TimeoutException`이 `RequestError`의 하위 타입이므로 한 곳에서 함께 잡아
429와 같은 백오프에 합류시켰다.

### 3-4. 백틱 인용이 각주로 안 잡힘 (PR #11)

사용자 신고로 발견. `안전·신뢰 AI 2026`에서 논문 제목이 그대로 노출됐다.

처음엔 **"모델이 인용을 안 했다"고 진단했는데 틀렸다.** 인용은 했고 괄호 대신
백틱을 썼다 — 서술부 인용 26건 중 **백틱 23건**. `_apply_footnotes`가 `(...)`만
찾아 아예 매칭을 시도하지 않았다.

→ 각주는 조회 시점 후처리라 이 수정만으로 **기존 110건에 즉시 적용**됐다.
해당 분석의 참고문헌이 14 → 31개가 됐고 나머지 109건은 변화 없었다(부작용 없음).

## 4. 단계별 결과

### 1단계 — 정량 지표 전수 집계

**문제**: `metrics_json`에 수치 33,796개가 이미 있는데 `stats.compute`가 하나도
집계하지 않았다. 수치는 LLM 보고서 표로만 나타나는데 그 표가 **논문 수와 무관하게
11~12행에서 포화**한다 → 500건 이상에서 **반영률 1.2%**.

**결과**: 재추출 110건이 3시간 20분·실패 0건으로 완료(예상 3~7일보다 훨씬 빠름).
PCE가 82건(7조각) → **447건 단일 그룹**. 수치 29,981개가 전 분석에서 집계됐다.

### 2단계 — 세부 보고서 보존

**문제**: 3단 reduce가 partial 10개를 만든 뒤 최종 1콜로 **다시 압축하고 버렸다.**
이 이중 압축이 인용률 붕괴의 직접 원인(단일 9.7% → 3단 5.6%).

**결과**: 재생에너지 2025에서 세부 보고서 9개 저장, 참고문헌 **14 → 134개(9.6배)**.
종합 보고서는 오히려 짧아졌는데(10,088 → 3,818자) 정량 표가 빠지고 "대표 성과 중심"
프롬프트로 바뀐 결과라 의도한 방향이다.

### 3단계 — Elsevier 초록 폴백

**결과**: CCUS 2026에서 **129/129 회수(100%)**. 분석 대상 175 → 304건(+74%),
분석률 46.7% → **81.1%**.

핵심 설계는 대상 3조건 중 **"DB에도 초록이 없을 것"**이다 — OpenAlex는 같은 논문을
매달 계속 초록 없이 돌려주므로, 이게 없으면 이미 회수한 논문을 매달 다시 받아온다
(연 36,000콜). 회귀 테스트로 못박았다.

실패 정책은 **KCI와 정반대**로 갔다. KCI는 *검색 소스*라 빠지면 모집단이 조용히
줄어 결과가 틀리지만, 이건 *보강* 단계라 빠져도 예전만큼만 분석되고 그 크기를
`no_abstract_count`가 드러낸다.

### 4단계 — 국가 파라미터화

**핵심 성질**: `papers`와 `paper_extractions`가 이미 국가 중립이라(추출 캐시 키가
`paper_key + subfield_id + model_ver`) 국가는 `Analysis`에만 붙이면 됐고,
**공동연구 논문이 여러 국가 분석에 걸려도 추출 LLM 비용이 한 번만** 든다.

**결과**: 차세대 메모리반도체 CN 2025 종단 실행 성공.

```
[검색] OpenAlex 821(전체 821) + KCI 0 → 병합 820
[초록회수] 대상 84건 → 회수 84건
```

**설계 시점에 API로 직접 세었던 821건이 파이프라인을 통과해 그대로 나왔다.**
귀속 4분류는 단독 637(77.7%) · 주도 56 · 참여 8 · 주도 미상 119 — 참여 기준만
썼다면 보이지 않았을 정보다. 기존 KR 분석은 변화 없었다.

## 5. 되돌아보며

### 잘 된 것

**추측 대신 실측.** 세 가지 가설(중문·학회논문·구독 필요)이 전부 틀렸는데, 매번
데이터를 먼저 봤기 때문에 잘못된 방향으로 코드를 쓰지 않았다. 특히 사후 LLM 정규화는
**설계 문서에 채택으로 적혀 있던 것**을 실측으로 뒤집었다.

**기본값으로 안전하게.** 4단계는 모든 새 파라미터의 기본값을 `KR`로 둬서, 백엔드만
머지한 시점에도 화면이 이전과 완전히 동일했다. 큰 변경을 두 PR로 나눌 수 있었던 이유다.

**결함을 확장 전에 잡았다.** 운영 중 발견한 4건은 전부 다국가에서 몇 배로 커졌을
문제다. 재추출이라는 "작은 실전"을 먼저 돌린 것이 결과적으로 유효한 리허설이었다.

### 틀렸던 것

| 판단 | 실제 | 교훈 |
|---|---|---|
| 결측률을 인용 상위 표본으로 측정 | 방향이 뒤집힘(KR > CN) | 비율은 전수로 재라 |
| "Elsevier는 구독이 유일한 관문" | 무료 키로 88% | 실제 키로 시험하기 전엔 단정하지 말 것 |
| "모델이 인용을 안 했다" | 형식이 달랐을 뿐(백틱) | 원문을 보고 판단하라 |
| 사후 LLM 정규화 채택 | 141배 비쌈 | 설계 문서도 실측으로 뒤집힌다 |
| p90을 지표 분포에 사용 | 90%가 최대값과 동일 | 공식의 경계 조건을 확인하라 |

### 남긴 함정

**`.env` 백틱 사고.** PR 본문을 셸에서 만들다 백틱이 명령 치환으로 해석돼
식별자가 사라진 일이 세 번 있었다. 파일로 전달하는 방식으로 고정했다.

**main 오푸시.** `cd backend` 이후 `git add -A`가 워크트리가 아닌 메인 체크아웃에서
실행돼 gitlink 한 줄이 main에 올라갔다. force-push 없이 revert 커밋으로 정리했고,
이후 모든 git 명령에 `-C <경로>`를 붙였다.

**컨테이너는 메인 체크아웃에서 빌드된다.** 워크트리에서 개발 중인 마이그레이션은
`docker compose up --build`로 확인되지 않는다. 임시 DB(`scratch0017`)에 0001→0017
전 구간과 다운그레이드를 돌려 검증했다.

## 6. 다음

**전체 재실행** — 3단계 효과를 전 분석에 적용. 약 $2.8, 분석 대상 약 13% 증가.

**5단계 — 국가 비교 보고서.** 설계는
[§7](superpowers/specs/2026-08-01-multi-country-expansion-design.md)에 있다.
오늘 확인한 함정을 프롬프트 금지 조항에 넣어야 한다:

- **보고서 길이를 정보량의 대리 지표로 쓰지 말 것** — CN이 논문 2.7배인데 종합
  보고서는 절반이다(세부 보고서가 그 차이를 받아낸다).
- 표본율·결측률 차이를 연구량 차이로 읽지 말 것(§4-1~4-3).

**5단계 이후 검토** — 지표별 논문 드릴다운, 원자료 이상값, 범위 표기 값
([§10](2026-08-01-expansion-findings.md)).
