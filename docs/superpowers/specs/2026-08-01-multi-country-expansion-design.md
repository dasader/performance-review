# 다국가 확장 설계 — 미국·중국·일본 등으로 분석 범위 넓히기

작성일 2026-08-01. 현재 한국(KR) 논문만 분석하는 파이프라인을 임의 국가로 확장하고,
장기적으로 국가별 비교 보고서를 만들기 위한 설계.

이 문서의 모든 논문 수·비율은 **2026-08-01에 OpenAlex API로 실측한 값**이다(추정이 아님).
실측에 쓴 비용은 총 $0.22. 추정치는 "추정"이라고 명시했다.

## 2. "그 나라의 논문"을 무엇으로 볼 것인가

이 서비스에서 국가는 **성과의 귀속 단위**다. 정의를 잘못 잡으면 비교 보고서의 결론이 통째로 바뀐다.

### 실측 — 정의에 따라 결과가 얼마나 달라지는가

재생에너지 2025년, 각국 인용 상위 200건 표본:

| | KR | US | CN | JP | DE |
|---|---:|---:|---:|---:|---:|
| 단독 (그 나라만 참여) | 22.5% | 17.5% | **39.0%** | 17.0% | 19.0% |
| 주도 (교신저자가 자국, 국제공동) | 75.5% | 54.5% | **86.5%** | **45.5%** | 53.0% |
| 참여만 (교신저자가 타국) | 16.5% | 36.5% | 7.5% | **47.0%** | 40.5% |
| 교신저자 정보 보유 | 92.0% | 91.0% | 94.0% | 92.5% | 93.5% |

**일본은 논문의 47%가 "일본이 주도하지 않은" 국제공동연구다.** 중국은 7.5%뿐이다.
참여 기준만 쓰면 JP와 CN의 숫자를 같은 의미로 읽게 되는데, 실제로는 전혀 다른 것을 세고 있다.

### 결정 — 참여 기준으로 수집하고, 주도 여부를 병기한다

- **수집(필터)**: 현행 그대로 `authorships.institutions.country_code:{cc}`.
  "저자 소속기관에 그 나라가 하나라도 있으면 그 나라 논문". OpenAlex **서버측 필터**라
  추가 비용이 0이다.
- **주도 판정**: `authorships[].is_corresponding`이 참인 저자의 소속국. 이 필드는
  **이미 `SELECT`에 포함된 `authorships`에 들어 있어 추가 API 호출이 없다**. 보유율 91~94%라
  실용적으로 쓸 수 있다(미보유 6~9%는 `주도 미상`으로 별도 표기).
- **통계에서 4분류**: 분석 대상국 `cc` 기준 — `단독` / `주도` / `참여` / `주도 미상`.
  `stats.compute`가 코드로 집계한다(숫자를 LLM에 맡기지 않는다는 기존 원칙 그대로).

교신저자 기준만 쓰는 안은 버렸다. OpenAlex에 교신저자-국가 서버측 필터가 없어
국가 무관 전량을 받아 클라이언트에서 걸러야 하고(재생에너지 세계 94,777건 → CN 25,466건),
페이징 비용이 20~50배로 뛴다. 같은 정보를 참여 필터 + 사후 집계로 얻을 수 있다.

### 필연적으로 남는 중복 계상

공동연구 논문은 참여국 모두에 계상된다(실측: AI 2025 KR 450건 중 US 공동 84건, CN 공동 34건).
따라서 **국가별 합계 > 전 세계 총합**이 된다. 이는 오류가 아니라 참여 기준의 정의상 귀결이므로,
숨기지 않고 비교 보고서 통계 표에 `단독/주도/참여` 3열을 항상 노출해 드러낸다.

## 3. 5,000건 상한과 표본 대표성

CN 재생에너지는 25,466건으로 상한의 5배다. 현행 `advance()`는 이 경우
`AnalysisTooLarge`를 던져 **분석 자체를 거부한다**(`total_count > max_papers_per_analysis`).
즉 확장하면 CN 11개·US 3개 세부기술이 그냥 실패한다.

### 실측 — 현행 절단은 무작위가 아니다

OpenAlex는 `search`가 걸린 질의에 기본적으로 `relevance_score` 내림차순을 적용하고,
이 점수는 인용수를 반영한다. 실측(CN 재생에너지 2025, 기본 정렬 200건):
인용 중앙값 56, **0인용 논문 0건**, 인용 정렬 상위 200건과 92건(46%) 중복.

따라서 현행 절단은 "무작위 5,000건"이 아니라 "relevance 상위 5,000건"이다.
다만 relevance는 텍스트 유사도가 섞인 불투명한 점수라 **국가 간 비교의 기준선으로 쓸 수 없다**.

### 결정 — 연도 내 인용수 상위 N건 (검증 완료)

`sort=cited_by_count:desc`를 항상 건다. 실측으로 확인한 것:

- **cursor 페이징과 병용된다.** 1페이지 끝 79회 → 2페이지 시작 79회로 단조감소가 페이지
  경계를 넘어 이어진다. 비용은 동일($0.001/콜).
- **연도별 정규화는 자동으로 성립한다.** `enqueue()`가 이미 연도마다 별도 `Analysis`를 만들고
  `query_hash(subfield, year, year)`로 단일 연도만 검색한다. 즉 정렬 대상 집합이 항상
  한 연도 안이므로, 오래된 논문이 인용을 더 쌓아 유리해지는 연도 간 편향이 개입할 여지가 없다.
- **당해연도도 정렬이 유의미하다.** 2026년 CN 재생에너지 18,003건의 인용 상위는 41·34·33회이고
  상위 200건에 0인용이 없다. 당해연도라 정렬이 무너질 것이라는 우려는 실측으로 기각됐다.

상한 초과 시 거부하는 대신 **상위 5,000건을 수집하고 표본임을 기록**한다:

- `AnalysisTooLarge` 하드 가드를 제거하고, `stats_json`에 `population_total`(OpenAlex가 보고한
  절단 전 전체 건수 = 이미 있는 `SearchResult.total_count`)과 `sampled`(bool)를 남긴다.
- 보고서 프롬프트와 화면이 이 값을 읽어 "전수가 아니라 인용 상위 N건 표본"임을 명시한다.

**남는 한계는 없애지 않고 드러낸다.** KR 재생에너지 2,157건은 전수인데 CN은 25,466건 중 상위
5,000건(19.6%)이다. 표본과 전수를 나란히 놓으면 CN의 평균 인용수가 구조적으로 부풀려진다.
모든 국가를 최소 건수(KR 2,157건)에 맞춰 자르는 안도 검토했으나, 그러면 "연구량 차이"라는
비교의 가장 중요한 신호를 버리게 되므로 채택하지 않았다. 대신 통계 표에 모집단·표본·표본율을
항상 병기하고, 비교 프롬프트에 **표본인 국가의 인용수를 다른 국가와 절대 비교하지 말라**고 못박는다.

## 4. 비대칭 — 확장하면 새로 생기는 왜곡

확장 자체보다 위험한 것은 **국가마다 다른 조건이 비교 결과처럼 보이는 것**이다.
아래 셋은 전부 실측으로 확인됐고, 전부 "제거"가 아니라 "표기"로 대응한다.

### 4-1. KCI 비대칭 — KR만 국내지가 잡힌다

현행 `search.collect()`는 OpenAlex + KCI를 병합한다. KCI는 한국학술지 전용이므로
**KR 분석에만 국내지가 포함되고 타국은 OpenAlex(영문 국제지 중심)만 잡힌다.**
이대로 비교하면 KR 논문 수가 구조적으로 부풀려진다.

→ **비교 보고서는 `source != 'kci'`인 논문만 쓴다.** `Paper.source`가 이미
`openalex`/`kci`/`both`를 구분하므로 코드 한 줄 필터로 소스를 대칭시킬 수 있다.
세부기술 보고서(단일 국가)는 지금처럼 KCI를 포함한다 — 한국 성과를 빠짐없이 보려면 필요하다.

### 4-2. 언어 편향 — 원리적 한계

검색식이 전부 영문이고 OpenAlex 색인도 영문 중심이라, **CN의 CNKI 중문지·JP의 국내 일문지는
거의 잡히지 않는다.** 검색식을 고쳐 해결되는 문제가 아니다.

→ 로드맵 점검의 "### 4. 이 점검의 한계" 절과 동일한 방식으로 처리한다:
비교 보고서 프롬프트에 한계 절을 강제해, 각국 수치가 **국제 학술지 기준 성과**이며
자국어 학술지 성과는 누락됨을 보고서 자체가 밝히게 한다. 빼면 읽는 사람이
"중국은 논문이 이만큼"을 전수로 오독한다.

### 4-3. abstract 결측률의 국가 편차

`mapper.pending_papers`는 abstract 없는 논문을 제외한다. 그 비율이 국가마다 다르다
(재생에너지 2025, 인용 상위 200건 표본):

| KR | US | CN | JP | DE |
|---:|---:|---:|---:|---:|
| 34.0% | 37.0% | **41.0%** | 29.5% | **17.5%** |

같은 1,000건을 검색해도 실제 LLM 분석 대상은 DE 825건, CN 590건이다.
`searched_count` 대비 `analyzed_count` 비율이 국가마다 최대 23%p 다르므로,
드러내지 않으면 "중국은 분석된 성과가 적다"로 오독된다.

→ `stats.compute`는 이미 `no_abstract_count`를 낸다. 비교 보고서 통계 표에
`검색 / 분석 / abstract 미보유`를 국가별로 나란히 싣고, 프롬프트에
**분석 건수의 국가 간 차이를 연구량 차이로 해석하지 말 것**을 명시한다.

## 5. 스키마 설계 — 새 테이블 하나, 새 컬럼 셋

### 핵심: `papers`와 `paper_extractions`는 손대지 않는다

`papers`는 이미 `countries_json`을 들고 있어 국가 중립이다. `paper_extractions`는
`(paper_key, subfield_id, model_ver)`가 키라 **국가와 무관**하다.

이것이 이 설계에서 가장 중요한 성질이다: **공동연구 논문은 KR 분석과 US 분석 양쪽에 걸려도
추출 LLM 비용이 한 번만 든다.** 추출 캐시가 그대로 히트한다. 국가는 `Analysis`에만 붙이면 된다.

### 마이그레이션 0016

```
analyses:
  + country VARCHAR(2) NOT NULL DEFAULT 'KR'
  uq_analysis_year: (subfield_id, year) → (subfield_id, year, country)

papers:
  + lead_countries_json JSON NOT NULL DEFAULT []   -- 교신저자 소속국 코드
  - korea_flag                                     -- 삭제 (아래 근거)

schedule_settings:
  + countries VARCHAR NOT NULL DEFAULT 'KR'        -- 콤마 구분. 스케줄러가 돌 국가.
```

기존 KR 분석 행은 `DEFAULT 'KR'`로 자동 귀속되므로 **데이터 손실·재실행이 없다.**

`korea_flag`를 삭제하는 근거: 전수 grep 결과 `search.py`(병합·upsert)와
`openalex.py`/`kci.py`(생성)에서 쓰기만 하고 **읽는 곳이 한 군데도 없다** —
`stats.compute`도 화면도 이 값을 보지 않는다. 국가가 파라미터가 되면 "한국인가"라는
단일 불리언은 의미 자체가 사라지므로, 국가별 조건으로 바꾸는 대신 지운다.
같은 정보는 `countries_json`에 이미 있다.

### 새 테이블 — `country_comparisons`

`FieldReport`/`RoadmapCheck`와 같은 큐잉 모델을 그대로 복제한다(검증된 패턴).

```
country_comparisons
  id, subfield_id FK, year
  countries VARCHAR(50)     -- 정렬된 콤마 문자열 "CN,KR,US" (키의 일부)
  status(pending|done|failed), error
  report_md TEXT, generated_at, source_count
  UNIQUE(subfield_id, year, countries)
```

`countries`를 **정렬해 저장**하는 이유: `KR,US`와 `US,KR`이 다른 행이 되면 같은 비교가
두 번 생성된다. 큐잉 시점에 정렬해 키를 정규화한다.

`FieldReport`와 합치지 않은 이유: 키 단위가 다르다(분야+연도 vs 세부기술+연도+국가집합).
한 테이블에 넣으면 두 종류 모두 NULL 허용 컬럼투성이가 된다.

## 6. 코드 변경 — 파일별

`Field`/`Subfield`/검색식은 **전혀 바뀌지 않는다.** 국가는 검색식이 아니라 필터이므로,
55개 중점기술 정의를 국가별로 복제할 필요가 없다.

| 파일 | 변경 |
|---|---|
| `clients/openalex.py` | `_filter_expr`에 `country` 파라미터(하드코딩 `KR` 제거), `sort=cited_by_count:desc` 추가, `_parse_work`가 `lead_countries` 추출(`is_corresponding` 기반), `korea_flag` 제거 |
| `clients/kci.py` | `korea_flag` 제거 |
| `services/search.py` | `collect(..., country)`. **`country != "KR"`이면 KCI 호출을 건너뛴다** — 타국 분석에서 만료된 KCI 키 때문에 무의미하게 failed되는 것을 막는다. `query_hash`에 country 포함, `merge_papers`/`upsert_papers`에 `lead_countries` 추가 |
| `services/stats.py` | `compute(..., country, population_total)`. `"KR"` 하드코딩 제거, `attribution`(단독/주도/참여/주도미상) 집계, `population_total`·`sampled` 추가 |
| `services/runner.py` | `enqueue(..., country)`, `advance()`가 `analysis.country`를 넘김, `AnalysisTooLarge` 하드 가드 제거(표본 수집으로 대체), `run_scheduled_if_due`가 `schedule_settings.countries`를 순회, 비교 보고서 큐 처리 한 종류 추가 |
| `services/reducer.py` | `enqueue_country_comparison` / `process_country_comparison` 추가(`FieldReport` 패턴 복제) |
| `app/prompts.py` | `MAP_INSTRUCTION`에서 "한국" 제거, `REDUCE_INSTRUCTION` 국가 파라미터화, `COMPARE_INSTRUCTION` 신규 |
| `routers/public.py`·`admin.py` | 조회·실행 경로에 `country` 쿼리 파라미터(기본 `KR`), 비교 보고서 조회/생성 |
| 프론트 | 국가 선택 UI, 분석 조회에 `?country=`, 비교 보고서 화면 |

### `MAP_INSTRUCTION`에서 "한국"을 빼도 캐시는 무효화되지 않는다

`model_ver()`는 `gemini_model`/`thinking_map`/`EXTRACTION_SCHEMA_VERSION`만 본다 —
**프롬프트 텍스트 변경은 추출 캐시를 무효화하지 않는다.** 논문 한 편에서 기술적 성과를
뽑는 작업에 저자 국적은 무관하므로 결과가 실질적으로 달라지지 않는다.

→ 따라서 **`EXTRACTION_SCHEMA_VERSION`을 올리지 않는다.** 기존 KR 추출 캐시가 보존된다.
올리면 KR 19,909건이 전량 재추출되어 $5.5가 근거 없이 나간다.

### 프롬프트 국가 표기

`REDUCE_INSTRUCTION`은 "한국 논문들에서 추출한"이 하드코딩돼 있다. 이를 국가명으로
치환하고, `reduce_subfield`가 붙이는 입력 헤더도 확장한다:

```
[세부기술: 차세대 메모리반도체 / 2025 / 중국]
```

기존 `[세부기술: 이름 / 연도]` 헤더가 H1 제목을 고정하는 역할을 그대로 이어받는다
(빼면 모델이 제목을 지어내 목록 화면과 어긋난다 — 실측된 실패).
국가가 빠지면 KR 보고서와 CN 보고서의 제목이 동일해져 구분이 불가능해진다.

## 7. 비교 보고서 — 세부기술 단위

### 왜 세부기술 단위부터인가

입력이 이미 완성된 국가별 세부기술 보고서 3~5건이라 **LLM 1콜**로 끝난다.
분야 단위는 국가 × 세부기술이라 컨텍스트가 크고, 어느 세부기술에서 벌어졌는지 추적이 어렵다.
세부기술 비교가 쌓인 뒤 그 위에 분야 rollup을 얹으면 되므로, 먼저 만들 이유가 없다.

### 처리 흐름 — 기존 큐잉 패턴 그대로

`FieldReport`와 동일하다: 관리자가 "생성"을 누르면 검증 후 `pending` 행만 만들고 즉시 응답,
실제 LLM 호출은 `runner.loop`이 **한 틱(30초)에 하나씩** 처리. 재생성 시 기존 `report_md`는
그대로 두고 `status`만 되돌려 처리 완료 전까지 이전 보고서를 계속 보여준다.

큐잉 시점 검증(→ 즉시 404/409):
- 세부기술이 존재하는가
- 요청된 **모든** 국가에 그 연도의 `done` 분석이 있는가 — 하나라도 없으면 409.
  일부만으로 만들면 "미국은 성과가 없다"로 오독된다.
- 국가가 2개 이상인가

### 입력 조립 — 숫자는 코드가, 서술은 LLM이

`stats.py`의 원칙("통계는 전부 코드로 집계한다 — 숫자를 LLM에 맡기면 틀린다")을 유지한다.
비교 보고서는 숫자 대조가 핵심이므로 특히 중요하다.

프롬프트 입력은 두 부분:

1. **코드가 만든 대조표** — 각국 `stats_json`에서 뽑아 조립. LLM은 이 표를 그대로 인용만 한다.

   | | KR | US | CN |
   |---|---:|---:|---:|
   | 모집단(전체) | 2,157 | 7,785 | 25,466 |
   | 수집 | 2,157 | 5,000 | 5,000 |
   | 표본율 | 100% | 64% | 20% |
   | 분석(abstract 보유) | 1,424 | 3,150 | 2,950 |
   | 단독 / 주도 / 참여 | … | … | … |
   | 인용 중앙값·p90 | … | … | … |
   | 성과유형 분포 | … | … | … |

2. **각국 세부기술 보고서 본문** — `## [국가명]` 아래에 이어붙임.

### `COMPARE_INSTRUCTION`이 반드시 강제해야 할 것

로드맵 점검 프롬프트에서 검증된 방식(금지사항을 명시적으로 못박기)을 따른다.

- **표본율이 100% 미만인 국가의 인용수·논문 수를 다른 국가와 절대 비교하지 말 것.**
  대조표의 표본율 행을 근거로 판단하고, 표본인 국가는 "상위 N건 기준"임을 매번 병기.
- **분석 건수 차이를 연구량 차이로 해석하지 말 것** — abstract 결측률 차이일 수 있다.
- **참여 기준의 중복 계상을 명시** — 국가별 합계는 총합과 다르다.
- **`## N. 이 비교의 한계` 절 강제** — 영문 국제지 기준이라 자국어 학술지(CNKI 등)가
  누락됨, 표본율 차이, abstract 결측률 차이를 보고서 자체가 밝힌다.
- 순위·점수를 만들어내지 말 것. "한국이 3위" 같은 서술 금지 — 표본 조건이 국가마다 다르다.

### 구성

```
## 1. 비교 개요        — 대조표(코드 생성)와 표본 조건 명시
## 2. 연구 규모와 구조  — 논문 수·주도 비율·국제공동 양상
## 3. 기술적 성과 대조  — 주제별로 각국이 어디에 집중했는지 (본문의 핵심)
## 4. 한국의 위치      — 앞선 지점과 비어 있는 지점
## 5. 이 비교의 한계
```

## 9. 단계

**Phase 1 — 국가 파라미터화** (마이그레이션 0016 + §6 코드 변경)
완료 조건: US 또는 CN 세부기술 1개를 종단 실행해 ①5,000건 표본 수집 ②3단 reduce 그룹
재분할 ③batch 처리 소요 시간을 실측하고, 기존 KR 분석이 재실행 없이 그대로 보이는 것을 확인.

**Phase 2 — 비교 보고서** (`country_comparisons` + `COMPARE_INSTRUCTION`)
Phase 1에서 최소 2개국 × 같은 세부기술·연도가 `done`이 된 뒤 착수.

**Phase 3 (필요해지면) — 분야 단위 비교 rollup.** 세부기술 비교가 실제로 쓸 만한지
확인되기 전에는 만들지 않는다.

## 10. 의도적으로 하지 않는 것

- **검색식의 국가별 복제** — 국가는 필터이지 검색식이 아니다. 55개 정의는 그대로 쓴다.
- **자국어 검색식(중문·일문)** — OpenAlex 색인이 영문 중심이라 검색식만 번역해도 잡히지 않는다.
  CNKI 등 별도 소스 연동이 필요한 별개 과제다.
- **국가별 예산 분리** — 현행 단일 일일 예산 + `paused` 재개로 충분하다. 국가별 우선순위가
  실제로 필요해지면 그때 넣는다.
- **분야 단위 비교 보고서** — Phase 3. 세부기술 비교의 유용성이 확인된 뒤.
- **`AnalysisTooLarge` 대체 가드** — 표본 수집으로 바뀌므로 상한 자체가 가드 역할을 한다.
