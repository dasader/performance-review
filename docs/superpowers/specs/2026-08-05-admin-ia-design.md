# 관리자 화면 정보구조 재편 — 산출물 계층으로 탭을 가르고, 생성을 한 곳에 모은다

작성 2026-08-05 · 상태: 설계 확정, 구현 전

## 문제

관리자 탭이 7개인데 **같은 대상이 여러 탭에 쪼개져 있고, 생성 버튼이 세 탭에 흩어져 대상 단위가 제각각이다.**

세부기술 하나의 현황을 보려면 두 탭을 오가야 한다.

| 탭 | 현황 | 생성 조건 |
|---|---|---|
| 분석 실행·상태 | 세부기술 × **연도** (KR만) | 단건 임의 (기술 1 × 연도범위 × 국가 1) |
| 자동 스케줄 | 실행 이력만 | 전체 일괄만 |
| 분야 보고서 | 분야 × 종합·점검 | 전체 일괄만 |
| 국가 비교 | **없음** | 임의 조합 (기술 1 × 연도 × 국가 자유) |
| 국가 현황 | 세부기술 × **국가** | 전체 일괄만 |

혼란의 뿌리는 두 가지다.

1. **현황을 보는 곳과 임의 조건으로 만드는 곳이 다른 탭에 있다.** 국가 비교는 만들 수는 있는데 뭐가 있는지 안 보이고, 국가 현황은 보이는데 전체 일괄밖에 못 만든다.
2. **일괄 버튼 5개의 "전체"가 서로 다른 것을 가리킨다.** 분야 10개인지 세부기술 55개인지 이름만으로 알 수 없다.

| 버튼 | 위치 | 대상 단위 |
|---|---|---|
| 지금 실행 | 자동 스케줄 | 전체 세부기술 × 연도 × 국가 |
| 종합보고서 전체 생성 | 분야 보고서 | 전체 **분야** |
| 로드맵 점검 전체 생성 | 분야 보고서 | 전체 **분야** |
| 1:1 비교 일괄 생성 | 국가 현황 | 전체 **세부기술** |
| 다국 비교 일괄 생성 | 국가 현황 | 전체 **세부기술** |

## 원칙

**탭은 산출물이 어느 계층에 속하는가로만 가른다.** "특정 기술의 무엇이든" → 세부기술 탭, "특정 분야의 무엇이든" → 분야 탭.

**현황과 생성은 같은 화면에 둔다.** 만들 수 있는 것은 전부 현황표의 셀이고, 셀을 체크해서 고른다. 이름 없는 "전체 생성"이 사라지고 대상이 눈으로 보인다.

## 탭 4개

| 탭 | 대상 | 보여주는 것 | 만드는 것 |
|---|---|---|---|
| **세부기술** | 55개 | 기술 × 국가 (연도 필터, 행 펼침 = 연도 이력) | 세부기술 분석, 국가 비교 |
| **분야** | 10개 | 분야 × 종합·점검·로드맵 (연도 필터) | 분야 종합보고서, 로드맵 점검 |
| **검색식** | 55개 | 세부기술·검색식 목록 | — (설정) |
| **자동화** | 전역 | 스케줄 설정·실행 이력 | 월간 자동 실행 (예약) |

흡수 관계:

- `분석 실행·상태` + `국가 현황` + `국가 비교` → **세부기술**
- `분야 보고서` + `전략기술로드맵` → **분야**
- `세부기술·검색식` → **검색식** (그대로)
- `자동 스케줄` → **자동화** (그대로)

## 세부기술 탭

```
연도 2026 ▾                                    [새로고침]
──────────────────────────────────────────────────────────
 분석 12건 · 비교 3건 선택됨          [ 선택한 15건 생성 ]
──────────────────────────────────────────────────────────
              ☑KR    ☑US    □CN    □JP    ☑국가비교
☑ 차세대메모리반도체  ●완료  ●완료  ●완료  ●완료   ●완료
☑ 양자컴퓨팅       ☑미생성 ☑미생성 □미생성 □미생성  ☑—
□ ▾ 재생에너지      ●완료   —      —      —      —
      2025        ●완료   —      —      —      —
      2024        △갱신필요 —     —      —      —
```

- **셀 하나 = 만들 수 있는 산출물 하나.** 국가 열은 그 국가의 세부기술 분석, 비교 열은 그 기술의 다국 비교.
- **열 머리글 체크 = 그 국가 전체**, **행 체크 = 그 기술 전체.** 일부만 선택되면 부분 상태(indeterminate).
- **`—`는 선택할 수 없다.** 상대국 분석이 없어 지금은 만들 수 없는 칸이므로 체크 자체를 막는다.
- **비교 열은 다국 하나만 그린다.** 1:1은 그 안에 들어 있으므로(2026-08-04 설계) 열을 따로 두지 않고, 셀을 누르면 그 안의 쌍 목록으로 간다.
- 행 펼침(`▾`)은 그 기술의 과거 연도 상태와 `△갱신 필요`를 보여준다.
- 미리보기(정밀 견적)는 셀 하나를 고른 상태에서 **[정밀 견적] 버튼으로 연다.** 상주시키지 않는다 — 호출 자체가 OpenAlex 과금이라 늘 떠 있으면 안 된다.

## 분야 탭

```
연도 2026 ▾
──────────────────────────────────────────────────────────
 종합 4건 · 점검 2건 선택됨            [ 선택한 6건 생성 ]
──────────────────────────────────────────────────────────
              ☑종합보고서   ☑로드맵점검   로드맵
☑ 반도체·디스플레이  ●완료      ●완료      v3.1 · 65목표 [편집]
☑ 미래에너지·원자력  ☑미생성    —대상아님   미등록       [등록]
      └ [편집] → 이 자리에 원문 편집기가 펼쳐짐
           판본명 [v3.1        ]
           원문   [ 마크다운 13KB … ]
           ⚠ 원문은 Gemini API로 전송됩니다
           [저장] [삭제]
```

세부기술 탭과 **같은 조작 규약**이다 — 체크해서 고르고 상단에서 실행.

`—대상아님`은 로드맵이 없어 점검을 만들 수 없는 칸이고, 바로 오른쪽 같은 줄에 이유(미등록)와 해결 수단([등록])이 있다. **로드맵을 분야 탭에 넣는 이유가 이것** — "점검이 안 돌아가네" → "로드맵이 미등록이구나"가 화면 이동 없이 이어진다.

로드맵 원문 편집기는 펼치기 전에는 그리지 않는다(13KB 텍스트영역이 표를 밀어낸다).

## 백엔드

### 조회 — `dashboard` 하나로 합치고 `comparison-grid`를 폐기

`GET /admin/dashboard`가 이미 국가·연도·`stale`·논문 건수를 전부 준다. **여기에 비교 상태만 얹으면** 세부기술 탭이 이 응답 하나로 그려지고, 행 펼침도 추가 요청 없이 된다.

`GET /admin/comparison-grid`는 폐기한다(같은 것을 한 연도만, 더 적은 정보로 준다).

비교 상태는 2026-08-04 설계의 `in_multi`를 그대로 쓴다 — 다국 비교 안에 든 쌍은 별도 행이 없으므로 "다국에 포함"으로 표시한다.

### 생성 — `POST /api/admin/queue` 하나로 통합

```jsonc
POST /api/admin/queue
{
  "year": 2026,
  "analyses":       [{"subfield_id": 3, "country": "US", "force": false}],
  "comparisons":    [{"subfield_id": 3, "countries": ["KR","US","CN"]}],
  "field_reports":  [1, 4],
  "roadmap_checks": [1]
}
→ { "queued":  {"analyses": 12, "comparisons": 3, "field_reports": 2, "roadmap_checks": 0},
    "skipped": [{"kind":"comparison",    "subfield_id":7, "reason":"상대국 분석 없음"},
                {"kind":"roadmap_check", "field_id":1,    "reason":"로드맵 미등록"}] }
```

화면의 "선택한 15건 생성"이 **이 호출 한 번**이다. 지금은 왕복이 15번이고 부분 실패를 화면이 각자 집계한다.

**`skipped`가 사유를 드러내는 것이 이 API의 요점**이다. 지금 `run-all`은 검증에 걸린 대상을 조용히 건너뛰고 건수만 준다("10건 큐잉, 3건 건너뜀") — 왜 건너뛰었는지 알 수 없다.

한 건의 실패가 나머지를 멈추지 않는다는 기존 규약(`field-reports/run-all`)은 그대로 지킨다.

**폐기**: `POST /admin/run`, `POST /admin/field-reports/run-all`, `POST /admin/comparisons/run-all`. 셋이 하던 일이 전부 `/queue`의 부분집합이다.

**유지**:

- `POST /admin/preview` — 단건 정밀 견적(이미 `country`를 받는다)
- `POST /admin/fields/{id}/report`·`/roadmap-check`, `POST /admin/subfields/{id}/comparison` — 공개 화면 `GeneratedReportSection`이 쓴다
- 로드맵 CRUD, 스케줄 API

### 비용 표시 — 백엔드 추가 없음

**분석 비용은 미리 알 수 없다.** `/admin/preview`가 OpenAlex를 실제로 호출해야 건수를 알 수 있고 그 호출 자체가 과금이라, 셀을 고를 때마다 돈이 나가는 화면은 만들 수 없다.

- **보고서류**(비교·종합·점검)는 실측 단가를 곱해 표시 — 재현 가능한 값이다
- **분석**은 건수만 표시하고 비용은 "검색 결과에 따라 달라짐"으로 명시. 같은 기술의 다른 국가·연도 실적이 있으면 참고값으로 보여준다("US 2025년 445편 기준 약 $0.11") — `dashboard`의 `searched_count`로 프론트가 계산한다
- 정밀 견적이 필요하면 `[정밀 견적]` 버튼으로 단건 미리보기를 부른다

단가는 `frontend/src/lib/cost.ts` 상수로 둔다(비교 $0.05 / 종합·점검 $0.03, 2026-08-05 실측). 설정으로 만들면 관리 지점만 늘고 어차피 추정치다. **모델을 바꾸면 이 값도 손봐야 한다**는 것을 주석에 남긴다.

### DB

**스키마 변경 없음.** 마이그레이션 0020이 마지막이고 이번은 순수 API·화면 재편이다.

## 에러 처리

- **부분 실패**: `queued`/`skipped`를 화면에 그대로 표시한다 — 건수와 사유별 목록.
- **401**: 기존 규약(`ApiError.status === 401` → `onUnauthorized`)을 그대로 쓴다.
- **선택 상태와 데이터 갱신의 독립**: 진행 중인 작업이 있으면 표가 5초마다 다시 읽힌다. 선택은 `(kind, id, …)` 키로 보관해 **갱신에 날아가지 않게** 한다. 갱신 후 사라진 대상(예: 삭제된 세부기술)은 선택에서 조용히 뺀다.

## 테스트

**백엔드** (pytest, 인메모리 sqlite)

- `/queue` 4종이 각각 올바른 행을 pending으로 만드는가
- 부분 실패: 상대국 분석 없는 비교·로드맵 없는 점검이 사유와 함께 `skipped`에 담기고 나머지는 정상 큐잉되는가
- 이미 pending·진행 중인 대상을 다시 큐잉해도 중복 행이 생기지 않는가
- 빈 요청(`{}`)이 200 + 전부 0인가
- `dashboard`에 비교 상태가 실리고 다국 안에 든 쌍이 `in_multi`로 오는가
- 폐기 엔드포인트 3개가 404인가 + 그것들을 쓰던 기존 테스트 정리

**프론트** (vitest — jsdom이 없어 순수 함수만)

핵심 로직을 `lib/selection.ts`로 뽑아 단위 테스트한다. **체크 상태 → 요청 본문 변환이 이 화면의 핵심이고 순수 함수로 떨어진다.**

- `toQueuePayload(selection)` — 체크 상태에서 요청 본문을 만든다
- `selectableCells(row)` — `—`(상대국 분석 없음)는 선택 불가
- `estimateCost(selection, history)` — 보고서는 단가 곱, 분석은 참고값 또는 미상
- 열·행 머리글 체크가 하위 전체를 반영하고, 일부 선택 시 부분 상태가 되는가

렌더링은 자동 검증 수단이 없으므로 **브라우저 확인 항목으로 남긴다**(각주 점프와 같은 취급).

## 단계 분할

한 번에 바꾸면 되돌리기 어려우니 4개 PR로 나눈다. **각 단계마다 화면이 정상 동작한다.**

| 단계 | 내용 | 화면 영향 |
|---|---|---|
| 1 | `/admin/queue` 추가 + `dashboard`에 비교 상태 추가 | 없음 (기존 화면 그대로) |
| 2 | 세부기술 탭 (분석 실행·상태 + 국가 현황 + 국가 비교 통합) | 탭 7 → 5 |
| 3 | 분야 탭 (분야 보고서 + 로드맵 통합) | 탭 5 → 4 |
| 4 | 구 엔드포인트 3개 제거 + 죽은 컴포넌트 삭제 | 없음 |

되돌려야 하면 그 단계만 revert한다.

## 하지 않는 것

- **탭을 3개 이하로 줄이지 않는다.** 운영을 한 화면에 몰면 표 2개 + 생성 버튼 4종이 한 화면에 쌓인다.
- **검색식 편집을 운영 탭에 넣지 않는다.** 검색식 변경은 `query_hash`를 바꿔 해당 연도 분석을 통째로 재실행 대상으로 만드는 조작이라, 현황을 보다가 실수로 건드릴 자리에 두지 않는다.
- **비용을 설정값으로 만들지 않는다.** 추정치이고 모델 교체 시 어차피 손봐야 한다.
- **1:1 비교를 별도로 생성하지 않는다.** 2026-08-04 설계 그대로 — 다국 안에 이미 들어 있다.

## 알려진 한계

- 화면 렌더링은 자동 테스트로 고정할 수 없다(jsdom 없음). 순수 함수로 뽑을 수 있는 만큼만 뽑고 나머지는 브라우저 확인에 맡긴다.
- 분석 비용은 선택 시점에 정확히 알 수 없다. 참고값은 과거 실적 기반이라 검색식이 바뀌었거나 첫 실행인 국가에서는 나오지 않는다.
- 국가 이름 표가 `lib/countries.ts`와 `prompts.py`에 이중 관리로 남아 있다(이번 범위 밖).
